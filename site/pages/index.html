What the current source implements

Control your stream outputs

A desktop-first control panel with a local ingest server and individually managed output processes.

↗

Six platform templates

Configure YouTube, Rumble, Facebook, LinkedIn, TikTok or Instagram using destination-specific server URLs and stream keys.

▤

Independent video profiles

Choose 4K, 1080p, 720p, portrait crop, portrait letterbox, or no re-encode for compatible sources and destinations.

⚡

NVIDIA NVENC option

Uses FFmpeg H.264 NVENC encoding when a compatible NVIDIA GPU and FFmpeg build are present, with a CPU fallback.

⟳

Independent retry logic

One destination failing need not stop the others. Per-destination status and process controls are in the source code.

♧

Locally stored configuration

Keys are encrypted with Windows user-scoped DPAPI on disk. Active FFmpeg command-line arguments still present a local exposure risk.

⌘

Designed for OBS Studio

OBS sends one H.264/AAC stream to a localhost MediaMTX relay. RelayDesk starts separate FFmpeg outputs.

Architecture

How RelayDesk works

OBS StudioSingle RTMP source
RelayDesk + MediaMTXLocal loopback ingest
FFmpeg output workersSeparate platform publishing

In the current architecture, each configured output uses its own FFmpeg worker. Even identical profiles are not yet encoded once and shared, so multiple 4K encodes can significantly burden CPU/GPU hardware.
